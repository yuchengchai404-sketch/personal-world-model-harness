# Runtime Operations
Read the relevant section for an event, not all sections before every reply.

## Topic change and recovery

Check whether the previous Topic Resume is current. Save only missing conclusions or unresolved work. Switch global STATE for an explicit substantive topic change, then recover the target Resume. Viewing another topic or doing maintenance is not a switch.

## Important cognitive increments

Check whether a new judgment, support, challenge, usable method or natural stopping point needs action. Keep the full explanation in the source Note; extend an existing asset, prepare a justified candidate or state why no separate asset helps. Do not create work merely to fill categories.

For transfer, record source, relationship, impact and recovery question at the target. When it becomes relevant, integrate, recognize existing coverage, defer with reason or decline. Significant challenges to Active Models need prompt attention.

## Approval and correction

Bind approval to the specific proposal. Execute within authorized scope and distinguish adoption from evidence. Preserve original wording and history.

Update the next real retrieval point: current claim, expression, Resume and live references as needed. A correction in a distant appendix is insufficient if the old headline remains misleading.

Stable USER changes need confirmation; temporary course objectives stay in Topic. Model changes follow the primary asset workflow and use Model Changelog for significant lifecycle or scope changes, with actual decision attribution.

## Closure

At full cognitive-topic closure, check whether relevant source-bound understanding, claims, methods, cases, expressions, preferences and cross-topic inputs have an appropriate disposition. No asset quota. Ordinary continuation and system work do not run the full audit.

## Human review

When requested, derive readable review from current knowledge: recognizable question, sufficient explanation, changes in understanding, useful expressions and source locators. Keep the content date explicit. Do not refresh every lesson or treat a layout edit as new knowledge.

## Maintenance and rollback

For significant changes, preserve recoverable affected versions, check current files before writing, and verify actual use. Roll back only the intended delta, not subsequent learning.

User-initiated periodic review checks changes, unresolved issues and a small rotating sample. Important faults get targeted checks. Close scoped fixes honestly; long-term benefit may remain untested without creating permanent pending items.
