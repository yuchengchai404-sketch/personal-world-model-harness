# 架构｜Current architecture
现行公开设计整理：2026-10-27。旧版架构可查 Git 历史。

## 目的先于结构

PWM 服务持续学习、理解、判断、表达与应用。知识数量、抽象程度和系统完整性不是共同终点。它既需要可靠接续，也需要令人愿意继续读、继续想的认知交付。

## 职责与维护位置

| 位置 | 维护什么 | 不维护什么 |
|---|---|---|
| AGENTS | 运行入口、路由、授权与交付要求 | 每项任务的完整方法 |
| CORE | 原则、认知职责、证据与采用边界 | 临时课程目标 |
| USER | 经确认的稳定目标、信息与偏好 | 所有项目的动态进展 |
| STATE | 全局当前主题、阶段、路由、跨主题待决 | 每个主题的完整结论和下一问题 |
| Topic Resume | 该主题当前理解、下一问题、未完事项与证据入口 | 全局 Current Stream |
| 四个工作流 | 著作学习、主题探索、独立复核、资产取舍 | 每轮强制输出栏目 |
| Operations | 切换、批准、关闭、重大变更等条件性操作 | 每轮必读清单 |
| Home | 导航与用途说明 | 第二份状态表 |
| Model Changelog | 重要模型变更的定位索引 | 重复完整论证或把候选准备记成用户批准 |
| History | 失败、旧版与变更依据 | 现行默认指令 |

“单一维护来源”指一项职责有明确维护位置，不是全系统只能有一个文件。冲突要核对职责、证据与有效批准，不能仅看修改日期。

## 三层协作

```text
认知执行：当前问题 → 恢复相关理解 → 研究、解释、反馈
持久资产：来源 / Note / Insight / Model / Case / 恢复点
阅读出口：界面学习 / 人的回顾 / 可复述表达
```

输出是同一份理解的不同用途，不是复制三遍。后台保存完整不能补救界面讲解不足；人的回顾需要重新组织解释，不能把机器摘要直接搬上地图。

## 外围而非膨胀的核心

Reader 获取并审视外部内容；信息观察窗关注领域变化；外部评审检查实际交付。这些可以独立使用，按需与 PWM 交换有来源和证据状态的材料。PWM 对长期认知接续负责，不必自己维护每个平台的抓取器。

认知回顾是派生出口：集中更新、明确快照时间、保留原文回查。界面修复日期与知识内容日期不同。私有实现中的离线工具并未随公开模板发布。

## 运行边界

本仓库提供声明式工作区与示例。文件读写、浏览、消息传递、权限隔离及工具安装由实际 Runtime 提供。不同平台需分别验证适配；Markdown 规则不构成技术隔离。

系统工作不替换认知主线。只有用户明确恢复某个主题的实质讨论，才按[路由](task-routing.md)切换。学习之外的维护不自动触发完整资产审计。
