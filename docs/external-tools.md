# 外部能力与评审

## Reader、观察窗与 PWM

| 部分 | 主要职责 | 交接边界 |
|---|---|---|
| 通用 Reader | 获取、理解、分析、质疑文章/视频，按需核验 | 可独立提供洞察；不默认维护个人知识体系 |
| 领域信息观察窗 | 发现重要变化，整理可读资讯，针对问题补查 | 借助既有资讯供给，不重复建设整个新闻产品 |
| PWM | 与已有认知对照、深入研究、内化、应用与接续 | 资讯不是课程；讨论不等于认可或沉淀 |
| 外部只读评审 | 独立检查规则、知识和真实交付 | 建议须核对，不自动产生写入授权 |

Reader 可以建议值得继续讨论的问题，不必被限制成字幕工具；也不必核验完所有事实才能交接。它要说清读了什么、哪些是推断、哪些尚未查证。

两种自然入口都应成立：外部读完再带入 PWM；或在 PWM 讨论中调用外置能力，回来继续同一问题。外置的是维护负担，不是把搬运负担交给用户。

## 轻量交接

保留来源、日期、读取范围（全文/片段、字幕/音频/画面）、关键命题和原文定位、分析与证据状态，以及已有疑问。无用户想法就不代写。

PWM 复用已有工作，对会改变当前判断的关键、遗漏或冲突处回查，不把摘要盲信为原文，也不全量重做研究。

观察窗可据获准读取的上下文判断相关性，不能声称默认知道整个账号。行业重要性与个人相关性分开，避免把当前暂时用不到的重要变化筛掉。已有资讯服务的热度、精选和推荐理由可作重要性参考，不是唯一排序标准。阅读页应独立讲清消息与背景，不要求用户另去上游补读；相关链接用于自选深读和查证。是否读取资讯、追踪频率和自动化均按明确请求。

## 只读评审的实际经验

私有实现提供范围清单、Markdown 读取与搜索，返回版本哈希和分页信息。曾出现服务支持参数而旧会话仍暴露旧参数的缺口；需要检查实际可调用接口，并在新会话完成分页和目录过滤实测，不能仅凭代码修改宣称端到端修复。

搜索为实时结果而非固定快照时，并发变化可能影响分页；正文可用预期哈希核对版本。这是接口设计经验，不是本仓库提供的服务保证。

只读不等于数据不会传给评审方。文件范围、账号权限、凭据和外部发送都必须另行控制；不得将私有连接配置提交公共仓库。

## 评审材料不能只有后台规则

Markdown 接口不能替代 HTML 操作、图片/PDF 阅读或未落盘教学原文。实际需要时，单独导出获准范围、版本清单和成品，不因此重传整个知识库。评审者说明哪些真的操作过、哪些仅由记录推断。

本仓库没有部署 Reader、观察窗、MCP 或上传任务，也未附凭据与私有聊天。
