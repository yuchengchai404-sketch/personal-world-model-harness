# Task Routing｜主题接续

## 按用户当前意图路由

| 请求 | 路由与状态 |
|---|---|
| 当前主题继续实质讨论 | 从该 Topic Resume 接续 |
| 在已有停放主题恢复实质讨论 | 确保旧主题检查点有效，切换 STATE，恢复目标主题 |
| 只查看、引用或查询旧主题 | 不自动切换主线 |
| 明确开始新的持续主题 | 创建主题及恢复入口；不为短问自动建任务 |
| 系统治理、配置、发布与功能维护 | 留 Hub 或用户指定执行窗口，不替换认知主线 |
| 归属确实影响结果且不清楚 | 先澄清，不强行建新主题 |

Hub 转交已授权的主题请求时，应保留用户原消息和必要材料入口。已经讲过的内容交接结论与证据状态，从未解处继续，不重复上课。运行环境不支持自动打开或跨任务消息时，可以用文件恢复点手动接续，不假称已经送达。

## 两层状态，不复制待办

STATE 记录全局主题、阶段、路由和跨主题待决事项。Topic Resume 维护局部结论、下一问题、未完事项和理解证据入口。完整原话、论证与来源留在正文。

暂停或切换前检查能否恢复；已有记录完整且没有变化，不重复写入。默认只有一个修改共享认知状态的实质主线，不把多聊天窗口误当安全并发机制。

## 跨主题贯通

只有联系能改变另一主题的结论、范围、行动或关键证据时才传递。完整解释留在来源主题；目标保存来源、关系类型、影响与恢复问题。

关系可用 supports / challenges / extends / applies_to。目标恢复时，明确整合、已有覆盖、延后或不采用；连线和送达本身不是整合，更不是效果验证。紧迫风险或对 Active Model 的实质挑战及时提示。

## English summary

Route by current intent, not keywords alone. STATE owns global routing; Topic Resume owns local recovery. Looking up a parked topic does not activate it. Maintenance does not displace learning. Cross-topic handoffs carry a meaningful change and a recovery question, not duplicated transcripts. Runtime messaging and concurrency still require actual platform support.
