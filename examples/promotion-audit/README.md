# Demo: Promotion Audit Learns from Failure

This is a sanitized system-iteration example.

## Initial discussion output

A Topic Note contained both:

1. several declarative claims about organizational dissent;
2. a reusable decision workflow:

```text
Before commitment
information + challenge + real exit
        ↓
Decision
decision owner + evidence + review condition
        ↓
Execution
coordinated action + limited discretion + emergency stop
        ↓
After action
review + accountability + correction or exit
```

## First Promotion Audit

The audit extracted the declarative claims but left the workflow only inside the long Topic Note.

Why this was a failure:

- future minimum Context could not retrieve the workflow independently;
- the audit implicitly equated “reusable knowledge” with “proposition”;
- a procedural judgment model was treated as supporting prose.

## User challenge

The user asked where the reusable judgment model had been preserved and why it had not become an asset.

## System correction

Promotion Audit was expanded to scan by artifact type:

- declarative Insight;
- causal mechanism;
- judgment / decision model;
- diagnostic checklist;
- reusable workflow;
- Case, State, and Preference.

The workflow became a `testing` Insight, not a Model.

## New side effect

A broader scan can over-produce Insights because many high-quality responses contain multiple useful structures.

The next test therefore asks:

- Does the artifact have independent retrieval value?
- Will it likely be reused across contexts?
- Is it non-duplicative and testable?
- Is the maintenance cost justified?

## Why this example matters

The Harness did not improve because the original design anticipated every problem. It improved because a real failure remained traceable, the user challenged the output, and the new rule was kept in `testing` rather than presented as settled best practice.
